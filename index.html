Hands-on Lab · Mobile / Network Security

Remote Android Access — Wireless ADB & scrcpy

Completed

Investigated authenticated remote access to an Android 11 device using Wireless ADB and scrcpy, with a focus on authentication, trust, network exposure, and defensive implications.

Environment Kali Linux + Android 11
Access Method Wireless ADB
Remote Interface scrcpy
Authentication Pairing + RSA host trust

What I did

  • Configured Android Wireless Debugging and paired the device with Kali Linux.
  • Established an authenticated ADB connection over the local network.
  • Verified the Android version and inspected the local ADB trust artifact.
  • Used scrcpy to interact with the Android device through the authenticated ADB channel.
  • Investigated the distinction between ADB host authorization and the Android device lock screen.
  • Performed controlled cleanup by disconnecting ADB and disabling Wireless Debugging.

Security observations

  • Modern Wireless ADB uses a pairing mechanism rather than simply trusting an IP address.
  • The ADB host's cryptographic identity is part of the device trust relationship.
  • ADB authorization does not automatically bypass the Android user's lock-screen authentication.
  • scrcpy inherits the security boundary of the underlying ADB connection.
  • Exposed or unnecessarily enabled debugging services increase the device's attack surface.
